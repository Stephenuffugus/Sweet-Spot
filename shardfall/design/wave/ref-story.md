## 1. THE `LORE` TABLE (banner `// ============ LORE ============`, line 1073)

One const, five sub-tables plus a sigil key:

```js
const LORE={
 world:{n:'...', d:`...`},          // one entry — the top-level codex page
 biome:{ surface:{n,d}, caves:{n,d}, fungal:{n,d}, ruins:{n,d}, forge:{n,d}, abyss:{n,d} },
 enemy:{ <enemyId>:{n,d[,boss:1]} , ... },   // bestiary, keyed by ENEMIES id
 frag:[ {id,depth,n,d}, ... ],               // ordered array, NOT an object
 sigil:{ <sigilId>:`...long text...` },      // bare template strings, keyed by SIGILS_DEF id
 class:{ <classId>:{n,d} },                  // keyed by CLASSES id
};
```

### Field contracts

| table | field | meaning / legal values |
|---|---|---|
| `world` | `n` | display name of the world page (`'The Shardfall'`) |
| `world` | `d` | body text, template literal, rendered through `loreHTML()` |
| `biome[k]` | key `k` | MUST equal a biome name from `BIOMES` (line 585): `surface`, `caves`, `fungal`, `ruins`, `forge`, `abyss`. Suite-8 asserts every `BIOMES` name has a `LORE.biome` entry. |
| `biome[k]` | `n`,`d` | codex title ("The Rim") and body |
| `enemy[k]` | key `k` | MUST equal an `ENEMIES` id. Suite-8: `Object.keys(ENEMIES).filter(k=>!LORE.enemy[k])` must be empty — **every enemy you add to the roster needs a bestiary entry or suite-8 fails.** |
| `enemy[k]` | `boss` | optional flag `1`; only effect is the codex list subtitle `'miniboss'` (line 3935). |
| `frag[i]` | `id` | unique string (suite-8: fragment ids unique). Free-form (`f1`…`f13`, `f11b`, `f12b`, `escape`). |
| `frag[i]` | `depth` | metres of run depth (tile-y minus `SURFACE`) at which the fragment becomes eligible to drop. **`depth < 0` means "not buried"** — it can never drop from a chest and must be granted by `discover('frag',id,…)` from an act (only `escape` today, granted in `doEscape()` line 3812). |
| `frag[i]` | `n` | diegetic artifact title ("Guild Notice, posted at the rim") — shown in codex list with `depth+'m'` subtitle, or `'not buried'` for depth<0. |
| `frag[i]` | `d` | body text through `loreHTML()`. |
| `sigil[k]` | key `k` | MUST equal a `SIGILS_DEF` key (`reroll`,`lock`,`echo`,`invert`,`graft`). Suite-9 asserts every sigil has a `LORE.sigil` entry. Value is a bare template string (no `{n,d}` wrapper) — codex uses `SIGILS_DEF[id].n` as title and `LORE.sigil[id]` as body (`loreEntry`, line 3947). |
| `class[k]` | key `k` | MUST equal a `CLASSES` key. Suite-8 asserts every class has lore. |

### `loreHTML()` — the rendering contract (line 1983) — READ THIS BEFORE WRITING TEXT

```js
function loreHTML(t){return String(t).trim()
 .replace(/\r/g,'')
 .split(/\n\s*\n/)
 .map(p=>p.replace(/\n/g,' ').replace(/\s+/g,' ').trim())
 .join('<br><br>')}
```

- A **blank line is a paragraph break** (`<br><br>`).
- A **single newline is source wrapping and becomes a single space**. You cannot render verse or
  hard line breaks — even fragment `f12b`'s ALL-CAPS lines collapse into one running paragraph
  on screen. Wrap your source anywhere; it will not show.
- Text is injected via `innerHTML` inside `<div class="lore">`. A literal `<` or `&` will be
  parsed as HTML — avoid them (existing lore uses none). The strings are JS template literals:
  no backticks or `${` inside; apostrophes are fine.

### How fragments unlock — the full flow (lines 2823–2843)

```js
function nextFrag(depth){
 // depth < 0 marks a fragment that is not buried anywhere — it is written by doing something.
 for(const f of LORE.frag)if(f.depth>=0&&f.depth<=depth&&!META.seen.frag[f.id])return f;
 return null}
```

- **Only chests drop fragments.** `openChest(ch)` computes depth
  `Math.max(0,Math.floor(ch.y/TILE)-SURFACE)`, then `nextFrag(depth)`; on a 55% roll
  (`chance(0.55)`) it discovers the fragment, toasts, and opens the `openFrag(id)` **modal**
  ("FRAGMENT RECOVERED / POCKET IT") — finding one is an event, not a log line.
- Fragments are handed out **shallowest-unseen-first** — array order, not random. Reading in
  order matters more than reading them all.
- Suite-8 asserts, exactly: fragment ids unique; **buried fragments (depth>=0) appear in the
  array in non-decreasing depth order** (`d >= depths[i-1]`); at least one fragment has
  `depth < 0`; an unburied fragment can never come out of `nextFrag`; shallowest unseen first;
  a discovered fragment never repeats; `nextFrag(0)` respects the depth gate; after all found,
  `nextFrag(9999) === null`.
- **Insert a new fragment at the array position its depth dictates** (note `f11b` at 2900 and
  `f12b` at 3000 are physically after `f12` at 2800 — depth order, not id order). Do not
  renumber existing ids: they are save keys in `META.seen.frag`.

### Voice — what the sixteen fragments and blurbs establish (match this or don't write)

- Short declarative sentences; the longest thought is carried by an em-dash, not a subclause.
- No exclamation marks anywhere in the corpus. Dread is delivered as understatement and
  bureaucracy ("Answering is not optional.").
- Fragments are **found objects**: notice, tally, survey, letter, log, roster, plate, drawing,
  testimony, note. The title (`n`) names the artifact and its condition; the body never
  explains what it means.
- Parenthetical asides in a second hand `(Beneath, in a different hand: …)` are the corpus's
  one formatting device.
- Bestiary is second-hand field advice: what it does, what mistake kills you, one dry joke.
- Sigil lore and the escape text address "you" directly and are complicit, not judgmental.
- Recurring motifs: "nine hundred years", the guild as deadpan institution, the thing below as
  patient/agentive, depth as attention.

### Field contract

| field | meaning |
|---|---|
| key | class id — save key in `META.classes`/`META.cls`, lore key in `LORE.class` |
| `n` | display name |
| `cost` | shard price to unlock at camp. **Classes are NOT in `UNLOCKS`** — suite-13's "shop is honest" check requires every `UNLOCKS` id to exist in `GEMS`/`GEAR`, so a class id there fails the suite. The buy flow is `openClasses()`→`buyClass(id)` and iterates `CLASSES` dynamically — no UI wiring needed. |
| `d` | one-line pitch shown on the class button (separate from the codex blurb in `LORE.class`) |
| `kit` | `{melee,ranged,armor}` — each value a `GEAR` base id (or shield in `ranged`). Applied in `newRun()` when `META.useClassKit!==false`. |
| `gem` | `{slot,id}` — free signature gem, pre-socketed into `EQ[slot].sockets[0]` at tier 1 in `newRun()` (line 3521); the socket's colour is FORCED to match (`it.sc[0]=GEMS[id].col`) so the kit is never dead on a colour roll. `id` must exist in `GEMS`. |
| `foc` | where the class earns Focus. ## 9. CAMP / PANEL MACHINERY (banner `// ============ UI: PANELS / TOAST ============`, 3549)

### The modal rules (CLAUDE.md rule 12)

```js
openPanel(html, modal, fn)   // line 3564
closePanel(force)            // line 3581 — the ONLY way out of a modal
backPanel()                  // line 3573 — honours UIROOT
```

- `modal=true` = the panel demands a choice (title, death, shrine, level-up, fragment, escape).
  Backdrop taps and cancel are ignored; only an explicit `closePanel(true)` from a button exits.
  A dismissable panel must NOT leave the game paused — `closePanel` sets `paused=false` unless
  dead.
- **Same-frame modal collision queues**: a second modal raised while one is up goes into
  `PANEL_Q` and reopens when the first closes (one swing can trigger level-up + fragment at
  once). **Death outranks everything**: `die()` clears `PANEL_Q` and opens YOU DIED under the
  `DYING` flag, which bypasses the queue; `openPanel` refuses anything while `P.dead && !DYING`.
- `fn` (third arg) is the panel's own builder, stored in `PANEL_FN` so the screen can be
  redrawn in place when the input device changes (every prompt label goes through
  `pr(action)` / `GLYPH` — rule 11; hard-coding "press E" is a bug). Pass it for any
  non-trivial navigable screen: `openPanel(h,false,openEcho)`.
- `UIROOT` = `'title'` | `'pause'` | `null`; `backPanel()` returns sub-screens to their root.
  Anything opened from the title returns to the title; `PANEL_FN===openPause` means BACK
  resumes.
- **Every menu is a stack of `<button>`s** (one focus cursor, dpad/arrow navigable). No divs
  with click handlers, no custom widgets. Disabled rows are `<button disabled>`.

### The camp panel (`openCamp`, 4017) — full structure

Reached from: title (`CAMP` button, hidden on the very first run) and pause (`CAMP` button,
only when `nearCamp()` — within 7 tiles of `CAMP_X` on the surface, or within 90px of the
run's `ANCHOR`). One scrolling stack:

CLASS — <name>                → openClasses()   (buy/pick classes, toggleKit)
DESCEND FROM — <biome>        → openAnchors()   (anchor list from BIOMES, free)

Every purchase handler (`buyUnlock`, `buyNode`, `buyClass`) mutates META, `saveMeta()`, and
